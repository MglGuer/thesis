\chapter{Design and Implementation}\label{chap:chapter5}

\section{Knowledge Base Design}

The knowledge base will serve as the foundation of the chatbot system, enabling accurate scenario generation, user profiling, and feedback delivery. It will consist of several interconnected components:

\begin{itemize}
    \item \hl{\textbf{Scenarios Table}} – It will store predefined conversational scenarios aligned with Grice’s Maxims and pragmatic principles.
    \item \hl{\textbf{User Table}} – It will maintain user profiles, including past conversations, performance data, and current proficiency levels.
    \item \hl{\textbf{Conversation Log Table} – It will store conversation logs for each user, enabling tracking of progress and performance over time.}
\end{itemize}


\section{Software Design and Implementation}


\hl{The chatbot system will be built on top of a large language model, namely Gemini-3 Flash (google-genai) SDK, implemented using Python (Flask Server Backend), and will follow a dual-agent system architecture, namely the AI Partner and the AI Mentor.

In this architecture, the system orchestrates multiple instances of \texttt{gemini-3-flash-preview}, each configured with specific "Thinking Budgets" and system instructions to balance real-time latency with deep pragmatic analysis.
}

\subsection{Agent Instances and Configuration}
\hl{To achieve nuanced pedagogical feedback, the system utilizes explicitly 4 configurations of Gemini-3 Flash:}

\begin{itemize}
    \item \hl{\textbf{AI Partner (Roleplay)} This instance is configured with a lower thinking budget (512 tokens) and prioritizes fast response times for fluid conversation.}
    \item \hl{\textbf{AI Mentor (Pragmatic Analysis)} This instance is configured with a higher thinking budget (8000 tokens) to allow for computationally heavy analysis of user responses. It utilizes a JSON schema containing the 3 categories and its 8 subcategories for the mapping of quantitative scoring.}
    \item \hl{\textbf{AI Mentor (Post-session Feedback)} This instance handles a medium thinking budget (1500) tokens for generating in-session feedback based on the analysis from the previous instance of the AI Mentor.}
    \item \hl{\textbf{Holistic Mentor} This instance is configured with a higher thinking budget (8000 tokens) similar to the pragmatic analysis instance. This agent focuses on aggregating user data and conversation logs to provide holistic and personalized feedback}
\end{itemize}

\subsection{System Workflow}
\begin{itemize}
    \item \hl{\textbf{DOM Load} - The Document Object Model (DOM) will load the user interface built on HTML, CSS, and Flask (Python).}
    \item \hl{\textbf{Profile Initialization} – Authenticate user and initialize their profile on the system (quantitative metrics and historical data).}
    \item \hl{\textbf{Holistic Analysis} - Utilizing the Holistic Mentor to analyze longitudinal metrics and user data to recommend a scenario that is suitable for the user's current needs.}
    \item \hl{\textbf{Scenario Selection} - After user elects to create a new chat, the system will load the scenarios list on the UI allowing the user to select from a list of scenarios to converse in.}
    \item \hl{\textbf{Load Dialogue Data} - Once the scenario is selected, the system will load the corresponding dialogue data and format the website to reflect the scenario's context and goals.}
    \item \hl{\textbf{System Prompts} - Load the system prompts utilizing the AI Partner (focused on roleplaying the scenario).}
    \item \hl{\textbf{Interact via conversation engine} – Engage in real-time dialogue with the user.}
    \item \hl{\textbf{Conversation End} - Once the user has decided to end the conversation, the system will then proceed to save the conversation to the database and align the conversation data to the user's profile.}
    \item \hl{\textbf{Pragmatic Analysis} - The AI Mentor will analyze the conversation data considering the quantitative scoring framework (Intention Coherence, Social \& Affective Nuance, and Communicative Effectiveness) to then give the user feedback on their performance and how they can improve in future conversations.}
    \item \hl{\textbf{In-depth Feedback} - The user can then proceed to click a button to question to gain further insight into their performance by continuing to speak to the AI Mentor which now takes into consideration the conversation data.}
\end{itemize}

\hl{
Firstly, the DOM will load with the Flask server, then user data will be received for authentication and profile initialization. This will allow the system to personalize the experience based on the user's history, metrics, and overall profile and pragmatic competence. 
Then, the implementation of the Holistic mentor will continue to analyze further the user's pragmatical scores and profile to then recommend a scenario that is suitable for the user's current needs. Once the user selects the button to create a new chat, the scenarios list
will load on the UI itself, allowing the user to select a scenario. Once the scenario is selected, the system will load the corresponding dialogue data and format the website to reflect the scenario's context and goals. This will then load the system prompts utilizing the 
AI Partner (focused on roleplaying the scenario). The user will then go through a back-and-forth conversation with the AI Partner employing system prompts focused on responding in a human-like manner while considering the social environment and the persona they're roleplaying.
Once the user has decided to end the conversation, the system will then proceed to save the conversation to the database and align the conversation data to the user's profile. Once done, this will continue to be analyzed by the AI Mentor considering the quantitative scoring framework
(Intention Coherence, Social \& Affective Nuance, and Communicative Effectiveness) to then give the user feedback on their performance and how they can improve in future conversations. The user can then proceed to click a button to question to gain further insight into their performance
by continuing to speak to the AI Mentor which now takes into consideration the conversation data.
}

\st{First, dialogue data, from the GRICE dataset, will be prepared and formatted to reflect various social communication scenarios. The
system uses predefined dialogue data drawn from the GRICE dataset. Real-time
conversation is handled via the Gemini API, which responds to user input using contextual understanding based on Gricean maxims
and the scenario’s goals. Subsequently, Gemini is loaded through an API to handle inference, while a data collator 
will be used to manage input lengths. Finally, the model engages in real-time econversations with users, providing contextually apropriate responses to support 
social communication training.
}

\section{Algorithms}

The system will rely on the following core algorithms to analyze input, assess pragmatic adherence, and generate appropriate responses:

\subsection{Intent Recognition}

The \textbf{Intent Recognition} algorithm is responsible for determining the user's intent based on their input. This ensures that the chatbot maintains contextual relevance and keeps the conversation focused on the right topic. By using an external API like Gemini, the system can classify user inputs into different intent categories, allowing for a more targeted and accurate response. The function works by sending the user's input to the Gemini API, which classifies the intent, and then returns the detected intent to guide the chatbot’s response.

\begin{lstlisting}[caption={Intent Recognition Algorithm}, label={lst:detectintent}]
FUNCTION detect_intent(user_input):
    INITIALIZE GeminiAPI with API_KEY
    CALL classify_intent on user_input using GeminiAPI
    RETURN detected intent from response
END FUNCTION
\end{lstlisting}


\subsection{Pragmatic Analysis}

The \textbf{Pragmatic Analysis} algorithm evaluates whether the user's response adheres to Grice’s Maxims, which are principles of communication that help maintain relevance, clarity, truthfulness, and informativeness. The algorithm checks for violations of these maxims by analyzing the user’s input. For example, it checks if the response is too short (Quantity Maxim violation), contains lies (Quality Maxim violation), is off-topic (Relation Maxim violation), or is unclear due to ambiguity (Manner Maxim violation). Based on the violations detected, the algorithm generates feedback to guide the user towards better communication practices.

\begin{lstlisting}[caption={AI Mentor Evaluation Algorithm}, label={lst:mentorlogic}]
FUNCTION evaluate_performance(transcript, scenario_context):
    LOAD response_schema FROM SCORING_RESPONSE_SCHEMA
    INITIALIZE GeminiInstance with thinking_budget=8000
    
    CONSTRUCT Analysis_Prompt:
        "Read this transcript and evaluate the user based on 
         Intention Coherence, Social Nuance, and Effectiveness.
         Context: " + scenario_context
         
    CALL GeminiAPI.generate_content(Analysis_Prompt, transcript)
    VALIDATE response matches response_schema
    SAVE scores and feedback to Supabase
    RETURN structured_report
END FUNCTION
\end{lstlisting}

\subsection{Feedback Generation}

The \textbf{Feedback Generation} algorithm constructs personalized feedback messages based on the pragmatic analysis. It informs the user about any violations of Grice's Maxims, offering suggestions to improve their communication. If no violations are found, the algorithm generates positive feedback, congratulating the user for providing a clear and relevant response. This ensures that users not only receive constructive criticism but also feel encouraged to continue improving their conversational skills.

\begin{lstlisting}[caption={LLM (Gemini API) Response Generation}, label={lst:generateresponse}]
FUNCTION generate_response(user_input, scenario):
    CREATE prompt with scenario and user_input
    CALL generate_text on GeminiAPI with prompt
    RETURN generated text from API response
END FUNCTION
\end{lstlisting}


\subsection{LLM (Gemini API) Integration for Response Generation}

The \textbf{LLM Integration} algorithm is responsible for generating responses that are contextually relevant and pragmatically sound.
This is achieved by integrating the Gemini API to generate text that aligns with the selected scenario and the user’s input.
The algorithm constructs a prompt that combines the scenario and the user’s input, and sends it to Gemini’s \texttt{generate\_text} method.
The generated text is then returned as the chatbot’s response. This ensures that the chatbot can handle various conversational
contexts and respond appropriately.

\begin{lstlisting}[caption={AI Partner Response Generation}, label={lst:partnergen}]
FUNCTION generate_partner_response(user_input, current_history):
    LOAD system_instruction (enforce natural Filipino conversational patterns)
    INITIALIZE GeminiInstance with thinking_budget=512
    
    CALL GeminiAPI.generate_content(system_instruction, user_input)
    RETURN character_response
END FUNCTION
\end{lstlisting}

\subsection{Linguistic and Safety Configurations}
\hl{Linguistic contextualization is achieved by forbidding the chatbot to have english translations in parentheses and enforce code switching in the prompts for relatability. Safety configurations for harassment and dangerous content are set to BLOCK\_ONLY\_HIGH to allow the AI Partner to engage in realistic social conflict without the model refusing the prompt while still considering emotional safety of the user.
}

\section{GRICE Dataset Structure}

\hl{The GRICE dataset played an important role in framing the chatbot's intent and the research's direction. As we have pivoted from training Mistral-7B to instead prompt engineering with Gemini, 
the dataset's structure was important in the training of Mistral.} Refer to Figure~\ref{fig:datasetstructure} for the structure of the dataset:

\begin{figure}[H]
    \centering
    \includegraphics[width=0.90\textwidth]{figures/dataset_structure.png}
    \caption{GRICE Dataset Structure}
    \label{fig:datasetstructure}
\end{figure}

The GRICE dataset is structured to include various scenarios based on the implicatures that come from Grice's Maxims. As such, each row of data in the dataset represents a unique social scenario in regard to a certain implicature. Described below are the columns in the dataset:

\begin{itemize}
    \item \textbf{question:} \hl{This column contains the initial utterance or query from a speaker. It sets the immediate context and prompts the response that contains the pragmatic information to be analyzed.}
    \item \textbf{answer:} \hl{This column provides the direct response to the question. Crucially, this response often contains a conversational implicature, meaning it is pragmatically appropriate but may not be literally direct.}
    \item \textbf{explicit answer:} \hl{This column serves as the ``ground truth'' for the implicature. It provides the fully resolved, explicit meaning of what the speaker intended to convey in the ``answer'' column, making the implied meaning clear and unambiguous.}
    \item \textbf{options:} \hl{This column frames the task as a multiple-choice question. It contains a list of possible interpretations for the ``answer'', which includes the correct ``explicit answer'' along with several incorrect or misleading distractors.}
    \item \textbf{answer index:} \hl{This column provides the zero-based index of the correct answer within the ``options'' list. It is used to programmatically identify the correct choice, which is essential for both training the model and evaluating its performance on pragmatic reasoning tasks.}
    \item \textbf{dialog id:} \hl{This column is a dialogue identifier that groups related question--answer pairs into a single, coherent conversation. This allows the system to maintain contextual continuity across multiple conversational turns, ensuring that the interpretation of any single utterance can be informed by the preceding dialogue.}
\end{itemize}
